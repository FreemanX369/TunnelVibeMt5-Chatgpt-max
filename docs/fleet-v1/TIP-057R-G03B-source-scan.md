## Finding that prevents a mechanical integration

Existing SDK calls execute in a long-lived MCP process or the existing tester orchestrator. G03-A supports either ARMED with proven zero attempts, or a BOUND worker with independently observed exact exit and a qualified descendant disposition. After SDK initialize is attempted, zero-attempt closure is unavailable. There is no separately created/bound SDK worker, and exiting the MCP/orchestrator would end the caller. Normal SDK shutdown, reconnect flags, a Python finally block or parent PID death cannot supply the missing worker/descendant evidence. Existing in-process callbacks therefore cannot close safely through the current worker contract.

The producer matrix also contains intentional persistent terminals, GUI effects on an externally owned terminal, nested capture utilities and privileged administrative control. They have different completion authorities. One all-purpose arm/finally-close wrapper would either retain ACTIVE indefinitely, clear uncertainty without evidence, kill an intentionally restored terminal, or deadlock by reacquiring a lease already held by the tester worker. Full G03-B requires an explicit lifecycle decision before code.

## Current authority can and cannot represent

`core/native_ownership.py`:288–337 arm/create_attempt/bind_worker revalidate the current actual parent and owned native token. Parent owns the native lease; worker must be independently observed live before bind. Schema `native.ownership/1` represents one ACTIVE operation and one worker identity, not an arbitrary sequence of simultaneous children or a persistent-session transfer. No production `.arm`, `.create_attempt`, `.bind_worker`, `.close_zero_attempt` or `.close_owned_worker` caller is found under `app`.

`close_zero_attempt`:356–361 permits only ARMED with no worker. Once CREATE_ATTEMPT is durable, even a create exception is unknown; the current interface has no positive zero-created-after-attempt closure. `close_owned_worker`:363–386 requires exact worker exit and a trusted verifier returning PREVENTED_BY_BOUNDARY or EXACT_DESCENDANTS_EXITED before full-snapshot CAS. There is no production verifier. A string from a callback, expected journal image, Boolean cleanup flag, legacy process receipt or function return is not independent OS evidence.

The source can technically close one fully proved phase and arm a later phase under the same still-owned lease. That does not make today's multi-effect worker safe: partial handoff, in-process SDK and intentionally persistent restart still lack their own closure authority; unjournaled transitions must not create a crash window. Representing an entire orchestrator as the bound worker would require a parent ownership/launch redesign, because today's worker owns its own lease and must continue preflight→compile→handoff→test→restore. No architecture is selected here.

Existing JobStore identity/command/job binding and exact role-stop remain useful separate evidence. They do not give G03-A retained-handle lifetime/qualified descendants. Clearing role records after stop, phase PASSED, job terminal states and native lease release never imply authority CLOSED. Worker finally at560–576 releases source/native metadata only; the G03-A barrier survives ordinary release.
