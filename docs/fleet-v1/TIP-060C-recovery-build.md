# TIP-060C — Coordinated control/job restore

Status: DISPATCHED as the 060 integration refinement. A checkpoint in Draft #65 remains immutable evidence; this extension has its own source/tests/report. Supported restore cannot be called complete while the control store remains permanently fenced or only the job journal is cleared.

YAGNI-3: control nonces/receipts and job intents must recover together; reuse A and 060 journals plus signed node witnesses; implement one concrete coordinator and a finite reconciliation lane, without generic SQL callbacks or a mark-ready boolean.

* Persist a joint restore scope: fresh challenge, restored control snapshot digest/revision/wall head, exact registered device/key/route set, job export generation/mapping digest and independent operator checkpoint reference. Fenced stages are PREPARED -> CONTROL_RECONCILIATION_COMMITTED -> JOB_FINALIZED -> CONTROL_READY last. Gateway dispatch checks both stores/coordinator readiness. Every phase is replayable under the same coordination digest; crash/fault at any boundary keeps dispatch fenced or fully reconciled.
* New exact signed `/fleet/v1/reconcile` lane accepts only complete scoped node journal + transport/control-head witness, while normal heartbeat/poll/results/start stay denied. The signature binds service audience, joint challenge, device/current key/route/session, record/high-water/control-head and pending outbound intents. Its nonce is retained atomically without permitting normal dispatch. Replayed/changed/partial/stale witness denies.
* Initial supported success is conservative coordinated-checkpoint restore with no missing control-ledger delta. Require every enrolled device's exact known control/admission head and complete resolved job mappings; pending/unknown/unmapped/outbound intents, higher/missing control head or key/route divergence stay fenced. Signed witness is node authority, not a physical uniqueness proof.
* A separate signed operator approval binds the exact independently retained quiescent checkpoint/current ledger head outside the restored database. It is an explicit operator approval of recorded facts, not DB-only anti-rollback detection or independent proof that no later operation happened. Missing external checkpoint, newer head, uncoordinated old valid backup or unavailable node cannot be cleared. Do not reconstruct lost grant secrets or erase operation/nonce evidence. Broader signed ledger-delta/key recovery remains an explicit unavailable outcome until implemented and qualified.
* Successful job reconciliation adopts exact observed outcome/local job/sequence before clearance, preserving original mapping and UNKNOWN where appropriate. Final control transition takes a concrete verified coordinator/journal receipt and stored full witness bundle, never a caller boolean or arbitrary force-clear.
* Keep versioned recovery metadata and explicit schema migration if A persistence changes; unknown/corrupt/old state never auto-bootstrap. No coordinated two-store phase may be inferred from one store's READY field alone.
* Tests include actual signed witnesses/operator approval, restore with no delta, missing/newer heads, key/route drift, lost nonce/admin proof, unknown rows and crash at every phase. Real deployment/old-backup topology qualification remains user testing after build.

Builder coordinates with B wire/service and M3 journal. Preserve failed and frozen A evidence; report source coverage and conservative unavailable cases honestly.
