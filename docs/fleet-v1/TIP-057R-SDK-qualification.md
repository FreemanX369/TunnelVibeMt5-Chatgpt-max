# Product SDK operator qualification and source handoff

This source prepares real state/account SDK observation behind an exact operator approval. No SDK, VM, account, installation ACL or AppContainer profile was used or changed during this build. A signed approval authenticates the operator's review of physical evidence. It does not turn a file labelled PASS into independently proved physical facts.

## Required later physical work

Complete the separately authorized Q2 manifest on the exact disposable host/session, Python/SDK wheel/DLL and two terminal bindings. Preserve matched unrestricted controls, restricted load/attach, stopped-terminal/race/no-birth, child and broker escape controls, parent crash and exact lifecycle cleanup. Preserve original raw traces and failures; synthetic/B1 harmless fixture evidence cannot qualify this capability. Each approved installation is one exact local device/terminal/generation/executable/data-root binding. Gateway route generation remains separate authenticated transport authority.

Prepare the approved fixed AppContainer profile `vibemql5.sdk.<32 lower-hex>` and exact SID outside normal read startup. Qualification includes actual Python/runtime/module/DLL/source and terminal-root resource ACL observations. The product launcher changes only a unique disposable IPC directory. It neither provisions a profile nor widens Python, source, authority or terminal permissions. Protected resources must grant the profile read/execute only; broad/profile write grants, null/unknown ACL grammar and missing exact ACL readback are denied. Authority files must be readable by the worker so it can independently require durable BOUND ownership of its own actual process. The ordinary targetless source path remains unchanged.

## Approval records

An envelope has exactly `approval` and a 128 lower-hex Ed25519 `signature` over `b"fleet.sdk.operator-approval/1\0" + canonical(approval)`. Canonical JSON sorts keys, uses compact separators and rejects nonfinite values. The locally configured trusted operator public key is 32 raw bytes and is never taken from an HTTP request or approval field. Private operator keys are generated and protected separately by the operator; they are excluded from source, logs, clone images and normal backups.

The approval fields are `schema="fleet.sdk.operator-approval/1"`, `scope="REAL_Q2_NO_START_STATE_ACCOUNT"`, ordered `operations=["state","account"]`, integer UTC `approved_at_ms` and `expires_at_ms`, `payload`, `installation`, `controls` and `summary`. Expired approvals deny. `payload_manifest()` returns the actual installed package Python sources and available dependency manifests as canonical absolute path to SHA256; the caller's expected manifest and signed payload must both match it exactly. Every package change requires a new matching approval. Stable hashing retains a read-only regular-file handle and reopens the current pathname before release. Windows uses one consistent Win32 FileId/basic/standard metadata source; it does not compare Python 3.12 handle stat aliases with path stat aliases. On Windows the shared read helper follows no reparse/symlink path and grants neither write nor delete sharing. The cumulative 512 MiB per-file cap and exact observed size remain enforced; changed files or names fail qualification.

Installation fields are `platform="Windows"`, actual decimal `os_build`, integer `session_id`, exact local `fleet.target/1`, `executable`, `data_root`, `authority_root`, fixed dedicated `python`, `python_dll`, `sdk_wheel`, loaded `sdk_dll`, the exact product `sdk_worker.py` path, `runtime_files`, `runtime_resource_manifest`, `profile_name`, `profile_sid`, `restrictions` and `scope_authority`. Runtime paths are absolute canonical files; `runtime_files` pins actual bytes including Python, Python DLL, SDK wheel, loaded SDK DLL, executable and the SDK package origin. Pin the complete dedicated runtime/dependency/import closure used by the physical candidate. The worker checks SDK import resolution before package execution and actual loaded package/extension identity before initialize.

`scope_authority` is null for the original global native authority, or exactly `{profile_sha256,owner_public_key,candidate_sha256,runtime_sha256}` for the separately installed signed physical capacity profile. The owner public key here authenticates that capacity profile; it never supplies the SDK operator trust anchor. A present scoped-install marker without matching approved scope authority denies, including corrupt/partial markers. A scoped SDK request carries only the exact `{profile_sha256,reservation_id,token}` sealed lease reference. SDK admission uses kind `ipc`, preserving one IPC producer per device, and retains the terminal's resource conflict scope. The worker verifies the profile and exact BOUND record without writing to control state. Synthetic capacity fixtures cannot open the public SDK path.

Worker request/result files retain a 32 KiB bound. Signed approval, resource ACL and raw control metadata have a separate 256 KiB bound to fit the complete installed source/runtime closure; resource snapshots admit at most 512 entries, and no metadata parser reads without a finite cap.

Restrictions are exactly `appcontainer=1`, `capabilities=0`, `child_policy=1`, `integrity_sid="S-1-16-4096"`, `inherits_handles=false`. These signed inputs are rechecked against actual retained creation-handle token/mitigation observations before resume and current worker observations before SDK import. No unrestricted fallback exists.

`runtime_resource_manifest` maps one snapshot path to SHA256. Its JSON is `{"schema":"fleet.sdk.runtime-acl/1","resources":{"<absolute resource>":"<actual DACL and selected-label SDDL>"}}`. Required resources include every pinned package/dependency file and runtime file, Python parent, package root, terminal executable/data root, authority root/state directory and approval file/parent; scoped installations also include their fleet state root. Include any additional runtime/source/SDK dependency resources from Q2. Activation compares current SDDL with every recorded value and mechanically checks that app/broad principals cannot write protected resources. Unknown/missing resources fail qualification rather than receiving a new ACL.

The complete control set is `LOAD`, `ATTACH_A`, `ATTACH_B`, `STOPPED_A`, `STOPPED_B`, `RACE_A`, `RACE_B`, `ESCAPE_CHILD`, `ESCAPE_BROKER`, `PARENT_CRASH`, `EXACT_CLEANUP`, `MATCHED_UNRESTRICTED_CONTROLS`. Each `controls[case]` is exactly `{path,sha256}` for a bounded reviewed record with fields `schema="fleet.sdk.q2.control/1"`, `case`, `evidence="REAL_Q2"`, `outcome="PASS"`, `candidate_sha256` and `raw_artifacts` (absolute path→SHA256). Candidate digest is canonical SHA256 of `{payload,installation}`. The operator must verify causal controls, trace completeness and effect/cleanup scope before approving these records; the loader checks their signed provenance, exact candidate and unchanged artifacts, not the truth of a physical event from a status word. Broker control must cover every permitted external launch path in the selected Q2 manifest; uncovered paths leave approval unavailable.

`summary` maps one path to SHA256 for `{schema:"fleet.sdk.q2.summary/1",evidence:"REAL_Q2",candidate_sha256,cases:<sorted complete control names>}`. No sample file carrying REAL_Q2/PASS is shipped by this source build. Unsupported persistent terminal handoff, compiler/tester phase chains, GUI restoration and arbitrary administrative paths receive no capability from this state/account approval.

## Explicit operator commands after real qualification

These source commands are prepared for later use. This build did not execute them with actual keys or physical evidence.

```powershell
python -m vibemql5.fleet.sdk_qualification sign <reviewed-unsigned-approval.json> --private-key <isolated-operator-private.key> --output <new-approval.json>
python -m vibemql5.fleet.sdk_qualification validate <approval.json> --public-key <trusted-operator-public.key>
```

Signing is create-exclusive and rejects malformed/incomplete/mismatched/fixture evidence; it does not generate a key, grant ACLs, start a process or activate SDK. Portable validation reports approval integrity only. Runtime activation additionally requires exact actual Windows build/session/profile/resource observations through `QualifiedSdkInstallation.from_operator_manifest(...)`. Configure the returned installation internally in local/node adapters; there is no caller-provided qualification flag.

## Runtime and failure contract

`read_local(root, concurrency, operation, target, installation, budget_ms=10000)` acquires the common native lease or exact installed scoped lease once, validates fresh registry attribution and independently retains the live terminal identity. `observe_under_owned_lease(...)` supports an existing native producer without acquiring another lease. Local route-positive calls deny before SDK. `QualifiedReadAdapter.read(command, admission)` requires the sealed admission issued from the node's current TLS-delivered READ envelope, claims it once, and freshly rechecks gateway authorization under the lease and before create/resume/result promotion. Its initial budget is the remaining absolute command deadline, capped at ten seconds, and later stages share that remaining total. Full requested target remains frozen in worker request/result; installation approval does not grant route/session authority. An SDK read does not authorize native phase chains or terminal restoration.

One node adapter accepts a singleton installation or a tuple/list of one to sixteen sealed installations. Each target keeps its own signed exact approval. All entries must share authority root, device, actual Windows session, fixed Python/SDK runtime, source worker and AppContainer/profile/scope family. Selection uses exact device/terminal/generation and retains the command's full route target; unknown, duplicate or stale generations never select another terminal. Two independently qualified bindings therefore share one outbound session and the existing IPC lifecycle authority.

Ownership is arm → committed create attempt → restricted suspended creation → independent full process identity → durable bind → resume. The worker independently requires current restricted token and exact durable BOUND self-identity. Only exact ARMED/no-attempt can close without a process. Creation/publication/bind uncertainty stays ACTIVE. Exact worker exit plus current exact operator-qualified preventive boundary is required for closure; shutdown return, a fixture string or a PID timeout cannot substitute. Parent waits/termination run outside authority transactions and never kill the target terminal.

The configured soft observation budget is at most 10 seconds, lease wait at most 2 seconds and process probe at most 2 seconds within that same total. Initialize is capped by the remaining budget and 2 seconds. Exact termination waits are separately bounded at 5 seconds; cleanup can exceed observation time and is reported honestly. Deadline/failure responses discard live account data and preserve earlier primary errors. Unknown cleanup retains durable exclusion and requires later exact reconciliation.

Authorization loss after proved worker closure and actual lease release discards the observation while retaining truthful CLOSED/PROVEN disposition. SDK cleanup is NOT_ATTEMPTED when admission fails before any SDK launch attempt. Actual release failure changes cleanup to UNPROVEN and preserves the earlier observation/authorization error as primary; failure receipts never retain terminal/account payloads.
