# TIP-044 — Byte-exact chart PNG export

Business C captured chart `67352` once after TIP-043. The backend returned `image/png` (27,102 bytes, 960×540), but C could not materialize those transient bytes into a local chat file: its subsequent filesystem tool call was blocked. The C agent could not observe the user's inline viewer or click its Download button. This report proves capture, not visible file delivery.

## Change

After the native screenshot lease is released, `capture_live_chart` saves the same validated PNG bytes under `exports/live-charts/` while holding the existing cross-client mutation lease. The result still includes the original `TextContent` and `ImageContent`, and now includes an `image/png` `ResourceLink`. Structured metadata includes `file_export` with the scoped `source_id`, byte count, SHA-256 and hash-bound URI. The existing `export_file(scope="exports", source_id=..., expected_sha256=...)` retrieves that file later without another chart capture. PNG export is allowed only within this archive, and the export reader checks scope, path, byte count and SHA-256 again.

The archive is limited to 64 PNG files and 64 MB; old links can expire as earlier files are pruned. No account, credential, AutoTrading or terminal configuration changes are involved. The default remains 16:9, and the catalog remains 79 tools. Build `TIP-044`, version `0.2.40`.

An MCP `ResourceLink` is a recoverable file reference. It is **not** a ChatGPT `file_id` or proof that a native attachment appears in the final chat. The TIP-043 viewer remains available and has its own user-observed UI gate.

## Acceptance on Business C

1. Refresh the C connector and start a new chat. Require `server_info` TIP-044 / 0.2.40, 79 tools, and health READY with queue and locks idle.
2. Select a current chart ID from `list_live_charts`. Call `capture_live_chart(chart_id=...)` **once**, without `aspect_ratio`.
3. Require `isError=false`, content types `text,image,resource_link`, MIME `image/png`, matching bytes and SHA-256, and `file_export.source_id` under `live-charts/`.
4. Call `export_file(scope="exports", source_id=file_export.source_id, expected_sha256=file_export.sha256)`; verify the same URI and bytes without a second capture. If the client can read the resource, compare PNG bytes/SHA-256 to the first capture.
5. User checks whether an inline image and a working Download PNG/file link appear in the final ChatGPT UI. Mark visible delivery PASS only on that observation. Report viewer, ResourceLink and native attachment separately; do not infer them from `isError=false`.

The one TIP-043 capture already made cannot be recovered by this new archive retroactively. The next capture after deployment will exercise the new path.
