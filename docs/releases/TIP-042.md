# TIP-042 — Bounded chart capture timeout

Business C observed `LIVE_CHART_CAPTURE_TIMEOUT` for the first default 16:9 capture of MT5-2 chart `67328` at 2026-09-26 01:48:37 +07:00. The native lease was acquired in 16 ms and the operation failed 6.19 seconds after acquisition; the fixed five-second disposable `PrintWindow` process timeout was reached. A prior retry of the same chart succeeded. This was not an invalid chart ID or an MCP parameter validation failure; the connector surfaced the backend exception as a generic `INVALID_ARGUMENT`.

The disposable chart capture process now has an eight-second timeout. It is still on demand, terminates on timeout, uses the same native FIFO lease, preserves the 3-megapixel and 8 MB PNG bounds, and restores the chart placement, minimized state, and active selection in `finally` on failure. There is no automatic retry. The MCP tool names, schema, `aspect_ratio="16:9"` default, and tool catalog digest remain unchanged.

Regression coverage simulates a render taking more than five but less than eight seconds, verifies the PNG is returned, and checks that a process exceeding the new bound still raises `LIVE_CHART_CAPTURE_TIMEOUT`. The existing failure-path rollback tests and Windows interactive acceptance cover the chart state around the isolated process. Release version `0.2.38`, build `TIP-042`.

## Client image delivery acceptance

After rollout, Business C reported one direct `capture_live_chart(chart_id=67328)` call with `isError=false`, `text` and `image` content, and MIME `image/png`. The shared native diagnostic event `LIVE-3DC769A951A8471F` completed at 2026-09-26 02:20:48 +07:00. C also reported forwarding the image block with `image(block)`, but the user did not see an inline image in C's final chat answer. Backend capture and MCP image content therefore pass; direct C chat UI display remains failed by user observation. The A-chat four-chart demo used temporarily generated PNG files embedded through `sandbox:` links, so it does not verify this C presentation path. No automatic downloadable PNG attachment or client-independent inline rendering is claimed by TIP-042.
