# TIP-045 — Show the newest available candle in chart captures

## Behavior

`capture_live_chart(chart_id=...)` sends MT5's `End` chart shortcut to the verified, focused chart view after the chart becomes renderable and before `PrintWindow` captures it. This applies to both the default 960×540 image and `aspect_ratio="native"`, including charts temporarily restored from a minimized state. The selected chart stays at the newest available bar after the screenshot; the user's Auto Scroll setting is not changed. Other charts are not navigated.

The existing native execution lease still serializes chart operations. Key messages use bounded Win32 dispatch to the GUI thread's focused child, after verifying its parent chart and exact executable. If another chart owns focus, the requested chart is activated and the prior selection restored after capture; if focus cannot be verified, capture fails explicitly. The 16:9 and minimized-chart paths still restore placement and minimized state. The PNG/ImageContent, hash-bound export, default 16:9 and 79-tool catalog are unchanged. Version `0.2.41`, build `TIP-045`.

The newest *available* candle depends on the MT5 price feed. Sending `End` establishes a navigation request but does not prove that the client processed the shortcut or that the broker supplied a newer candle. The user-visible screenshot is the acceptance evidence for its right edge.

## Acceptance on MT5-2 and Business C

1. Check `server_info` = TIP-045 / 0.2.41, `health` READY, queue and locks idle, and A/B/C each one process with `healthz/readyz=200/200`.
2. Use `list_live_charts` for the current chart IDs. Capture a chart previously scrolled into history once with `capture_live_chart(chart_id=...)`; keep the default 16:9. Do not toggle Auto Scroll or attach an EA.
3. Confirm PNG 960×540, `file_export` SHA-256/bytes, and visible newest available candles at the chart's right edge. Compare the user-visible image with the previous history view. If the viewport did not advance, mark this acceptance FAIL even if the Win32 message and capture returned success.
4. Check chart IDs, placement, minimized states, active selection, health, locks and A/B/C tunnel readiness after capture. The selected chart's horizontal scroll position is intentionally left at the latest bar.

## Acceptance correction

The first TIP-045 implementation sent End to the MDI frame. A live XAUUSDm/M1 capture remained on 23 September 2026 while MT5 had M1 bars through 25 September 20:57 UTC. Sending or posting the key to the parent frame did not navigate. The chart's keyboard focus was on an `AfxFrameOrView140su` child of chart `67352`; bounded End down/up messages to this exact-process child produced a screenshot with the 25 September candles and newest bar near the right edge. Before/after PNG SHA-256: `2fe024a8e58a716a5fe6fa780e331d442e073e52bec75041ae6e0cf962586775` / `01828c27cd4b30ae83e07770c42dd28fb96f7b6320bac895195c98eeef83398a` in the diagnostic probe.

The temporary diagnostic test was restored from its backend checkpoint. Local unit tests cover focused-child binding, dispatch and rollback. The Windows unit suite and final post-update live screenshot are separate gates.
