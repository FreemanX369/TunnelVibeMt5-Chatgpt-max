# TIP-043 — Show the captured chart in ChatGPT

## Observed gap

Business C called `capture_live_chart(chart_id=67328)` once after TIP-042. The MCP result contained `text` and `image/png` blocks with `isError=false`, but the image forwarded by the agent was absent from the user's final ChatGPT message. The earlier A-chat demo produced local `sandbox:` PNG files and therefore used a different delivery path. Backend capture success did not prove chat delivery.

## Change

`capture_live_chart` now advertises an MCP Apps inline viewer at `ui://vibemql5/live-chart-r1.html`. The viewer reads the **same** PNG `ImageContent` from the complete MCP tool result, displays it in the chat, and offers a `Download PNG` link to those bytes. It also accepts the MCP Apps `ui/notifications/tool-result` event. There is no second screenshot, VPS file persistence, account change, or trade action. The original text, image block, structured metadata, `chart_id`, `aspect_ratio="16:9"` default, and 79-tool catalog stay intact.

This is a viewer with a direct PNG download inside the chat, not a claim that an MCP `ImageContent` automatically becomes a native ChatGPT file attachment. The host's iframe and download behavior must be verified on Business C. Other MCP clients still receive the original image block without depending on the viewer.

For hosts with a local artifact workspace, the server instructions also tell the assistant to save the exact returned image bytes as a PNG and embed/link that file when a native chat attachment is requested. This is a client-side delivery step, not a second screenshot or a server-side export.

## Acceptance

1. Refresh the Business C connector and start a new chat so the new UI resource and tool metadata load.
2. Read `server_info`: require `TIP-043`, `0.2.39`, and `live_chart_widget_uri=ui://vibemql5/live-chart-r1.html`; check `health=READY`, queue/active/native/mutation locks idle.
3. Get a current `chart_id` from `list_live_charts`, then call `capture_live_chart(chart_id=...)` **once** with default parameters. If capture fails, preserve the error/diagnose and do not mark delivery PASS.
4. Require `isError=false`, `image/png` MCP content, an inline chart viewer visible to the user in the **final chat**, and a working PNG download of that same chart. Check dimensions and chart ID against the tool metadata. User observation on C is the final presentation gate.
5. If the viewer/download is absent, report `CLIENT_DELIVERY_FAIL` and retain the tool result and UI behavior as evidence. Do not substitute a manually generated image, a previous A-chat file, or `image(block)` for this acceptance.

Local unit and JavaScript harness checks establish wiring and extraction of image content. They cannot certify the ChatGPT C UI; that result remains pending until the direct C test above.

Business C later ran one default capture on `XAUUSDm/M1`, chart `67352`: MCP PNG was 27,102 bytes at 960×540. Its agent could not observe the user's viewer/download UI, and a later attempt to move the transient image payload into a chat file was blocked by the client safety tool. This does not establish that the viewer was absent. TIP-044 adds a server-side file export so later captures can be retrieved without depending on that transient payload.
