# TIP-041 — Default 16:9 live chart capture

`capture_live_chart(chart_id, aspect_ratio="16:9")` returns a 960×540 PNG of the **chart client area** for a chart ID returned by `list_live_charts`. It captures on demand from the fixed running MT5-2 interactive session. To preserve the earlier original-size behavior, use `aspect_ratio="native"`; any other value is rejected before changing chart windows. One call captures one chart, so call it once for each ID when several charts are open.

For 16:9, the bridge first verifies the chart belongs to the exact MT5-2 process and MDI client, snapshots the original placement of all charts, their minimized states and the active chart. A minimized or visible chart is temporarily assigned a 972×575 outer rectangle, which produced a true 960×540 client rectangle on the verified MT5-2 VPS. The chart is captured through the existing disposable `PrintWindow` process with its 5-second limit. The bridge checks the client rectangle and the returned PNG dimensions, then restores the original chart placement and verifies all chart placement fields, minimized states and active selection. Rollback also runs if a Win32 message, placement change, or image capture fails. The metadata reports `aspect_ratio`, `resized_temporarily`, `restored_temporarily`, `image_width` and `image_height`.

The fixed 972×575 outer size relies on the MT5-2 window chrome observed on this VPS. A different DPI or window chrome that does not yield exactly 960×540 fails closed with `LIVE_CHART_16_9_SIZE_UNVERIFIED`. An MDI client smaller than 972×575, an unverifiable chart, a tiny visible chart, or a failed layout rollback also fails closed. The operation may visibly reposition a chart briefly; its MCP annotation stays `readOnlyHint=false`. It does not change account, credentials, AutoTrading or trading state. The connector tool **schema** must be refreshed in connected clients to expose the new optional parameter and default; the count and ordered names of the 79 server tools remain unchanged.

Local regressions cover the MCP default and `native` opt-in, PNG dimensions, minimized charts with an original rectangle larger than native capture limits, a visible chart with mixed MDI states, failure after a placement message was dispatched, capture failure, tiny chart rejection and rollback checks. Interactive Windows acceptance runs through every currently open chart under the native lease and checks a 960×540 PNG and exact placement/minimized/active restoration after each capture. Local non-Windows runs skip that real-terminal test. Release version `0.2.37`, build `TIP-041`.
