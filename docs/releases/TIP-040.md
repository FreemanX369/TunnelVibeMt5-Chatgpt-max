# TIP-040 — Live MT5-2 observations

## Tools

| Tool | Source | Returns |
| --- | --- | --- |
| `get_terminal_live_state` | Running MT5-2 via Python MetaTrader5 IPC | Account, connection, last ping and positions/orders counts |
| `get_account_snapshot` | Same on-demand accessor | Same snapshot for account-focused calls |
| `list_live_charts` | Win32 chart child windows belonging to the exact configured MT5-2 executable | Unique `chart_id` (HWND), symbol, timeframe, visibility, client size |
| `capture_live_chart(chart_id)` | Win32 client-only `PrintWindow` of an exact-process chart, with temporary restore/rollback if minimized | MCP `ImageContent` (`image/png`) and small metadata |
| `read_terminal_journal(source, limit)` | The fixed MT5-2 data root | Bounded tail of `journal` or `experts`; default 100, maximum 200 lines |
| `inspect_terminal(include_logs)` | The sources above under one native lease | Account, connection, charts, installed EA file counts, optionally both bounded logs |

Examples: call `inspect_terminal(include_logs=true)` to inspect the terminal in one request; call `list_live_charts`, then pass the desired unique `chart_id` into `capture_live_chart`. Two XAUUSD M1 charts remain distinct. The selected chart must belong to the running fixed MT5-2 interactive Windows session. The image response has a PNG content block plus `image_width`, `image_height` and `restored_temporarily` metadata; it is not embedded as base64 text in the log or metadata.

The account accessor calls only `initialize`, `terminal_info`, `account_info`, `positions_total`, `orders_total`, and `shutdown`. It requires the fixed installation to be **already running** before initialization; it validates both the returned installation path and data root. A failed binding aborts the request. When disconnected, financial fields and current ping are null. `ping_last_us` is the last recorded ping in microseconds; `ping_ms` converts that value only while connected. Account trade flags describe what MT5 reports; use bounded Journal context when investigating the cause of disabled trading.

Every IPC/chart/log request takes the existing native MT5 execution lease with a 2-second wait limit, so it cannot overlap a tester/compile handoff. There is no persistent telemetry EA, timer, tick handler, or polling. Screenshot runs in a disposable process with a 5-second timeout, a 3-megapixel capture bound and an 8 MB PNG response bound. The captured client area must pass chart/process identity checks before and after rendering; errors fail closed. When every chart is minimized, a selected minimized chart with a safe saved rectangle is briefly restored through the verified MDI client (2-second bounded message), captured on demand, then minimized again in `finally` (bounded asynchronous rollback and 3-second placement verification). Original chart placements and the active chart selection are verified after capture; failure to verify rollback fails the request. This visible transient GUI effect is reflected by the MCP tool annotation `readOnlyHint=false`; it does not change account, AutoTrading or trading state. Journal reads only the latest daily log, at most 128 KiB, and masks common credentials and account numbers before returning lines. Installed EA inventory counts filenames under the fixed `MQL5/Experts` directory on request, with a 10,000-file scan bound and no file-content reads. `.ex5` is a file count, not the number of distinct production EAs.

## Proven limits and deviation

The installed Python MetaTrader5 package exposes account and terminal properties but does not expose chart enumeration or MQL5 `ChartScreenShot()`. The local MT5 MCP chart and screenshot tool schemas have not been established. TIP-040 therefore uses Windows chart child windows and an isolated Win32 capture rather than claiming native `ChartScreenShot()` access. `list_live_charts` reports EA attachment and indicators as `UNKNOWN`; window titles and saved `.chr` profiles cannot prove them. Direct children of the verified MT5 MDI area with valid symbol/timeframe captions are counted even when their client size is 0×0; they return `renderable=false` in inventory. A zero-size chart can be captured only if minimized with a safe saved rectangle and all chart placements can be verified and restored. A visible but tiny non-minimized chart still fails closed. An empty verified MDI returns zero charts; an unknown direct child fails closed. Precise EA/indicator inventory needs a separately verified in-terminal `ChartGetString(chart_id, CHART_EXPERT_NAME)` path.

## Acceptance

The unit suite covers running-installation binding, wrong-data-root rejection, disconnected-account handling, ping conversion, unique chart selection, PNG `ImageContent`, minimized-chart restore/rollback including capture failure and a message timing out after dispatch, log bounds and redaction. A Windows-only smoke test checks the live running idle MT5-2 account/network, GUI charts, actual PNG and return to all original minimized placements and active selection. The smoke selects an inactive eligible chart when possible to exercise active-selection rollback. A passing cross-platform suite alone is not a live screenshot acceptance. Release requires the Windows smoke test against the production capture path in the interactive VPS session and refreshed model-visible connector schema for A/B/C.
